# ลูกโลกสถานการณ์โลก (ฉบับอัปเดตตัวเอง)

หน้าเว็บลูกโลก 3 มิติภาษาไทย สรุปความขัดแย้ง เศรษฐกิจ ช่องแคบสำคัญ ราคาตลาด 13 รายการ ข่าวล่าสุด และแผงทองคำ
เผยแพร่ด้วย GitHub Pages ที่ <https://zyser007.github.io/global-analysis/>

ราคาและข่าวอัปเดตเองด้วย GitHub Actions:
- **ราคา 13 รายการ ทุกชั่วโมง** ด้วยสคริปต์ `updater/prices.py` ที่ดึงราคาตรงจากแหล่งข้อมูลฟรี (ไม่ผ่าน AI ไม่ใช้คีย์ ไม่มีค่าใช้จ่าย ดูตาราง [แหล่งราคา](#แหล่งราคา))
  แล้วเขียน `site/data/market.json` และ `status.json`
- **ข่าวและสรุปรอบ วันละ 2 รอบ** (08:00, 20:00 น.) ด้วย `updater/update.py full` ที่ให้ Claude (โมเดล `claude-sonnet-5-5`) ค้นข่าว
  แล้วเขียน `headlines.json` และ `status.json` (รอบนี้ไม่ค้นราคาแล้ว ใช้ราคาจากรอบดึงตรงที่รันก่อนหน้าในงานเดียวกัน)

จากนั้นบอตจะ commit กลับเข้า `main` และสั่งเผยแพร่หน้าเว็บใหม่ หน้าเว็บดึงไฟล์ทั้งสามทุก 10 นาที และทุกครั้งที่ผู้ใช้กลับมาที่แท็บ

แท็บ **ภัยพิบัติ** ใช้ไฟล์ `site/data/disasters.json` ที่สคริปต์ `updater/disasters.py` ดึงจากแหล่งฟรีโดยตรง ไม่ผ่าน AI และไม่มีค่าใช้จ่าย:
GDACS (เหตุการณ์เตือนระดับส้มและแดง: แผ่นดินไหว พายุหมุนเขตร้อน น้ำท่วม ภูเขาไฟ ไฟป่า ภัยแล้ง) และ USGS (แผ่นดินไหวสำคัญในสัปดาห์ล่าสุด `sig` ≥ 600 หรือ PAGER ตั้งแต่สีเหลือง)
แผ่นดินไหวที่อยู่ในทั้งสองแหล่งจะแสดงครั้งเดียว ชื่อเหตุการณ์ภาษาไทยสร้างจากแม่แบบ รันทุกรอบของงานตั้งเวลา (ทุกชั่วโมง) แยกจากตัวอัปเดตราคาและข่าว

ข้อมูลพื้นฐาน (ความขัดแย้ง เศรษฐกิจ ช่องแคบ ตัวชี้วัด) และบทวิเคราะห์ทองคำ (`data/gold.json`) ฝังอยู่ในหน้าเว็บตอนสร้าง
ผู้ช่วยบรรณาธิการ (Claude Managed Agents) ค้นข่าวและอัปเดตไฟล์ทั้งสองวันละครั้งตอน 07:00 น. ดูรายละเอียดใน [`editor-agent/README.md`](editor-agent/README.md)
ไทล์ตัวชี้วัดที่มีราคาสดตรงกัน (Brent, ทองคำ spot, DXY, S&P 500 ตาม `tools/live_indicators.json`) แสดงค่าจาก `market.json` พร้อมเวลาของค่านั้น และใช้ค่าที่ฝังไว้เมื่อโหลดราคาสดไม่ได้
หน้าเว็บจึงติดป้ายวันที่ของข้อมูลชุดนี้ไว้ (`meta.basis_th` ใน `data/world-data.json` และ “บทวิเคราะห์ ณ …” ในแท็บทองคำ)

แท็บ **ทองคำ** ใช้ราคาสดจาก `market.json` (`gold`, `gold_th` พร้อม `buy` และ `ornament_sell` ถ้าประกาศเดียวกันมีให้) แทนค่าที่ฝังไว้เมื่อ `as_of` ใหม่กว่า
ทุกรอบที่เขียน `market.json` ตัวอัปเดตจะต่อจุดราคาใน `site/data/gold_history.json` (ข้ามรอบที่ `as_of` ไม่เปลี่ยน เก็บไม่เกิน 400 จุด) ให้กราฟและการเปลี่ยนแปลงรายวัน
สร้างไฟล์นี้ใหม่จากประวัติ git ได้ด้วย `.venv/bin/python -I updater/backfill_gold_history.py`
เนื้อหาเป็นข้อมูลประกอบการติดตามข่าว ไม่ใช่คำแนะนำการลงทุน

## สองมุมมองของหน้าเว็บ

ปุ่มบนหัวหน้าสลับระหว่าง **อ่านง่าย** (หน้าเดียวเลื่อนยาว ไม่มีลูกโลก) กับ **ลูกโลก** (แผงเดิมพร้อมแท็บ) ทั้งสองใช้ข้อมูลชุดเดียวกันและกฎเตือนข้อมูลเก่าหรือโหลดไม่สำเร็จชุดเดียวกัน โหมดอ่านง่ายไม่มีเนื้อหาที่เขียนเพิ่ม มีแค่หัวข้อและป้ายกำกับ

- เลือกมุมมองตามลำดับ: `?view=read` หรือ `?view=map` ใน URL, ค่าที่ผู้ใช้เคยเลือก (`localStorage` คีย์ `world-view`), ความกว้างจอ (ไม่เกิน 600 พิกเซลเป็นอ่านง่าย นอกนั้นเป็นลูกโลก)
- three.js และลูกโลกเริ่มโหลดเมื่อเปิดมุมมองลูกโลกครั้งแรกเท่านั้น โหมดอ่านง่ายจึงไม่ดาวน์โหลด
- ความรุนแรงแสดงเป็นคำควบกับตัวเลข ตาม `RD_SEVERITY` ใน `tools/template.html`

## ตั้งค่าครั้งแรก

ต้องมี [GitHub CLI](https://cli.github.com/) (`gh`) ที่ล็อกอินแล้ว หรือทำผ่านหน้าเว็บ GitHub ก็ได้

1. **ส่งโค้ดขึ้น GitHub**
   ```bash
   git push -u origin main
   ```
2. **เปิด Pages ให้เผยแพร่จาก GitHub Actions**
   หน้าเว็บ: Settings → Pages → Build and deployment → Source เลือก **GitHub Actions**
   หรือคำสั่ง:
   ```bash
   gh api -X POST repos/zyser007/global-analysis/pages -f build_type=workflow
   ```
   จากนั้นสั่งเผยแพร่ครั้งแรก: `gh workflow run pages.yml --repo zyser007/global-analysis`
3. **ใส่คีย์ API เป็น secret ของ repo** ชื่อ `ANTHROPIC_API_KEY` (ใช้เฉพาะรอบ full ที่เขียนข่าว รอบราคาไม่ใช้คีย์)
   หน้าเว็บ: Settings → Secrets and variables → Actions → New repository secret
   หรือคำสั่ง (โปรแกรมจะถามค่าคีย์ ไม่ต้องพิมพ์คีย์ลงในบรรทัดคำสั่ง):
   ```bash
   gh secret set ANTHROPIC_API_KEY --repo zyser007/global-analysis
   ```
   คีย์ถูกอ่านจากตัวแปรสภาพแวดล้อมนี้เท่านั้น สคริปต์ไม่พิมพ์คีย์ออกมา และไม่มีคีย์อยู่ในไฟล์ใดของ repo
4. **ตั้งวงเงินใช้จ่ายรายเดือน** ใน Anthropic Console (Settings → Limits) เช่น 80 ดอลลาร์ต่อเดือน
   ถ้าใช้ครบวงเงิน การเรียก API จะล้มเหลว หน้าเว็บจะแสดงค่าล่าสุดพร้อมคำเตือน ไม่เสียหาย

## รันด้วยมือ (รันทดลอง)

หน้าเว็บ: Actions → **Update live data** → Run workflow → เลือก `prices` (ราคาอย่างเดียว ฟรี) หรือ `full` (ราคา + ข่าวด้วย Claude)
หรือคำสั่ง:

```bash
gh workflow run update.yml --repo zyser007/global-analysis -f mode=prices
gh run watch --repo zyser007/global-analysis          # ดูจนจบ
gh run view --repo zyser007/global-analysis --log      # ดูบันทึก รวมจำนวนโทเค็นและค่าใช้จ่าย
```

หน้าสรุปของรอบนั้น (Summary) แสดงตารางราคา 13 รายการ (ค่า เวลา แหล่ง) และสำหรับรอบ full แสดงการใช้โทเค็น จำนวนครั้งที่ค้นเว็บ และค่าใช้จ่ายโดยประมาณ
ทุกรอบต่อท้ายหนึ่งแถวใน `updater/cost-log.csv` (รอบราคา: `model` = `free-feeds`, ค่าใช้จ่าย 0, `requests` = จำนวนคำขอ HTTP, `items_changed` = จำนวนราคาที่เปลี่ยน)

## ตารางเวลา

ส่วน `schedule:` ใน `.github/workflows/update.yml`

| รอบ | เวลา UTC (cron) | เวลากรุงเทพฯ | ทำอะไร | ค่าใช้จ่าย |
|---|---|---|---|---|
| prices | นาทีที่ 7 ทุกชั่วโมง (`7 * * * *`) | ทุกชั่วโมง xx:07 | ภัยพิบัติ + ราคา 13 รายการจากแหล่งฟรี | 0 |
| full | 01:00, 13:00 (`0 1,13 * * *`) | 08:00, 20:00 | ภัยพิบัติ + ราคา (เหมือนรอบ prices) แล้วข่าว 12–16 ข่าว + สรุปสถานะด้วย Claude (ค้นเว็บ ≤ 14 ครั้ง) | ~0.25–0.35 ดอลลาร์ |

GitHub อาจเริ่มรอบตามตารางช้ากว่ากำหนดได้หลายนาที (บางครั้งข้ามรอบเมื่อระบบหนาแน่น) รอบที่ทับกันจะต่อคิว ไม่รันซ้อน
บอตจะ commit เฉพาะเมื่อไฟล์เปลี่ยนจริง และสั่งเผยแพร่ Pages เฉพาะเมื่อไฟล์ใน `site/` เปลี่ยน (ราว 24–26 commit ต่อวัน เพราะ Bitcoin และไฟล์สถานะขยับทุกชั่วโมง)

## แหล่งราคา

`updater/prices.py` ลองแหล่งตามลำดับ ใช้แหล่งถัดไปเฉพาะเมื่อแหล่งก่อนหน้าล้มเหลวหรือไม่มีค่าใหม่กว่าค่าเดิม
ขอข้อมูลครั้งเดียวต่อสัญลักษณ์ต่อรอบ ใส่ User-Agent ของโปรเจกต์ หมดเวลา 15 วินาที ไม่ลองซ้ำ (ตารางเดียวกันอยู่ใน docstring และ `sources()` ของสคริปต์)

| รายการ | แหล่งหลัก | แหล่งสำรอง |
|---|---|---|
| Brent | CNBC `@LCO.1` (ICE Brent สัญญาใกล้สุด) | Yahoo Finance `BZ=F` |
| WTI | CNBC `@CL.1` (NYMEX) | Yahoo `CL=F` |
| ทองคำ spot | CNBC `XAU=` | Swissquote ราคาเสนอซื้อ/ขาย XAU/USD (ค่ากลาง เทียบกับค่ารอบก่อน) |
| ทองคำแท่งไทย | API ของกระดานราคาสมาคมค้าทองคำ (goldtraders.or.th): ครั้งที่ เวลา แท่งขายออก/รับซื้อ รูปพรรณขายออก | ตารางประกาศรายวันของเว็บเดิม classic.goldtraders.or.th |
| DXY | CNBC `.DXY` (ICE) | Yahoo `DX-Y.NYB` |
| S&P 500 | Cboe delayed quotes `_SPX` | Yahoo `^GSPC`, CNBC `.SPX` |
| Nasdaq 100 | Cboe `_NDX` | Yahoo `^NDX`, CNBC `.NDX` |
| Bitcoin | CoinGecko | Coinbase Exchange (ราคาล่าสุด + ราคาเปิด 24 ชม.) |
| ดอลลาร์/บาท | CNBC `THB=` | Yahoo `THB=X` |
| ยีลด์สหรัฐ 10 ปี | CNBC `US10Y` (Tradeweb ระหว่างวัน) | Yahoo `^TNX` (Cboe คำนวณ 08:00–15:00 นิวยอร์ก), US Treasury par yield รายวัน (ทางการ ค่าปิด) |
| VIX | Cboe `_VIX` (Cboe เป็นผู้คำนวณ) | Yahoo `^VIX`, CNBC `.VIX` |
| SET | CNBC `.SETI` | Yahoo `^SET.BK` |
| Nikkei 225 | Nikkei Indexes (ผู้คำนวณดัชนี) | Yahoo `^N225`, CNBC `.N225` |

ไม่ใช้: Stooq (มีหน้าตรวจเบราว์เซอร์ด้วย JavaScript แล้ว), set.or.th / settrade.com (มีระบบกันบอต), API ของ ธปท. (ต้องลงทะเบียนรับคีย์)
CNBC, Yahoo, Swissquote, Cboe CDN และ CoinGecko เป็น endpoint สาธารณะที่ไม่มีเอกสารรับรองการใช้งาน อาจเปลี่ยนหรือจำกัดอัตราได้ ระบบจึงมีแหล่งสำรองทุกรายการ
ราคาเป็นข้อมูลประกอบการติดตามข่าวบนหน้าเว็บที่ไม่หารายได้ ดึงชั่วโมงละครั้งต่อสัญลักษณ์ และลิงก์กลับไปที่หน้าราคาของแต่ละแหล่ง (`source`)

`change_th` สร้างจากตัวเลข เช่น `+0.74% (+0.71) จากปิดก่อนหน้า`, `ปิด 3 พ.ย. −1.07% (−16.13)`, `ปิดภาคเช้า 4 พ.ย. …`,
`… · ตลาดปิดเสาร์–อาทิตย์`, `+1.78% (+1,361) ใน 24 ชม.` (Bitcoin), `−1.1 bp จากปิดก่อนหน้า` (ยีลด์),
`ประกาศครั้งที่ 28 เวลา 13:03 น. +50 บาท · +1,450 จากวันก่อน` (ทองไทย) เวลาทำการเป็นเวลาวันธรรมดา ไม่รู้วันหยุดของแต่ละตลาด
ถ้าอยู่ในเวลาทำการแต่ไม่มีราคาใหม่ 3 ชั่วโมงจะเขียนว่า “ยังไม่มีการซื้อขายใหม่ (อาจเป็นวันหยุดตลาด)”
`note_th` บอกว่ารายการใดเป็นราคาระหว่างวัน รายการใดเป็นราคาปิด รายการใดใช้แหล่งสำรองหรือดึงไม่สำเร็จ

## ค่าใช้จ่ายโดยประมาณ (รอบ full)

ราคา Claude Sonnet 5.5: อินพุต 2 ดอลลาร์ต่อล้านโทเค็น เอาต์พุต 10 ดอลลาร์ เขียนแคช (5 นาที) 2.50 ดอลลาร์ อ่านแคช 0.10 ดอลลาร์
ค้นเว็บ 10 ดอลลาร์ต่อ 1,000 ครั้ง (ค่าคงที่อยู่ใน `PRICE` ของ `updater/update.py`)
เปิดหน้าเว็บด้วย web fetch ไม่มีค่าบริการต่อครั้ง จ่ายเฉพาะโทเค็นของเนื้อหา (จำกัดรอบ full 4 หน้า หน้าละไม่เกิน 8,000 โทเค็น)

| รอบ | ประมาณการ | ที่มา |
|---|---|---|
| prices | 0 ดอลลาร์ | ดึงตรงจากแหล่งฟรี ไม่เรียก API ของ Claude |
| full | ~0.25–0.35 ดอลลาร์ | ข่าวอย่างเดียว ค้นเว็บ ≤ 14 ครั้ง เปิดหน้าเว็บ ≤ 4 หน้า (รอบ full เดิมที่ค้นราคาด้วยใช้ 0.34–0.43) |
| ต่อเดือน | ≈ 15–25 ดอลลาร์ | full วันละ 2 รอบ × 30 วัน (เดิม ≈ 60 ดอลลาร์เมื่อ Claude ค้นราคาวันละ 6 รอบ) |

ตัวเลขนี้เป็นการประมาณก่อนรันจริง ผลการค้นเว็บนับเป็นโทเค็นอินพุตทุกรอบที่โมเดลอ่าน จึงแกว่งได้มาก
ให้ดูตัวเลขจริงจาก `updater/cost-log.csv` หลังรันทดลอง แล้วปรับวงเงินใน Console ตามนั้น

## ระบบกันพลาด

- ผลลัพธ์ต้องผ่าน JSON Schema ใน `updater/schema/` ทุกไฟล์ ค่าตลาดต้องเป็นตัวเลข
- ค่าตลาดที่ขยับเกิน 15% จากค่าเดิมจะไม่ถูกใช้ ระบบคงค่าเดิมไว้และเขียนใน `change_th` ว่า “ค่าเดิม รอยืนยัน”
- ราคาที่เวลา (`as_of`) เก่ากว่าค่าเดิมไม่ทับค่าเดิม ราคาที่เวลาอยู่ในอนาคตเกิน 10 นาทีหรือเก่ากว่า 10 วันถือว่าแหล่งนั้นเสีย
- รายการที่ดึงไม่สำเร็จจากทุกแหล่งคงค่าเดิม และ `change_th` ขึ้นต้นด้วย “ค่าเดิม (ดึงราคาไม่สำเร็จรอบนี้)” ถ้าดึงไม่สำเร็จเกิน 6 รายการ
  ถือว่ารอบนั้นล้มเหลว: `market.json` เดิมยังอยู่ `status.json` เป็น `ok: false` และงานใน Actions ขึ้นสีแดง
- เขียนไฟล์แบบสลับทีเดียว (ไฟล์ชั่วคราวแล้วแทนที่) ไม่มีไฟล์ครึ่ง ๆ กลาง ๆ
- ถ้ารอบใดล้มเหลว (คีย์ผิด เกินวงเงิน โมเดลปฏิเสธ ผลลัพธ์ไม่ผ่านการตรวจ) ไฟล์ราคาและข่าวเดิมยังอยู่
  `status.json` จะเป็น `ok: false` พร้อมเหตุผลภาษาไทย หน้าเว็บแสดงคำเตือนสีส้ม และงานใน Actions จะขึ้นสีแดง
- หน้าเว็บทำเครื่องหมาย “ข้อมูลเก่า” เมื่อราคาเก่ากว่า 6 ชั่วโมง (บอตรันทุกชั่วโมง จึงเท่ากับพลาดราว 5 รอบติดกัน) (ข่าว 14 ชั่วโมง เพราะอัปเดตวันละ 2 รอบ)
- ภัยพิบัติ: ถ้าแหล่งใดแหล่งหนึ่ง (GDACS หรือ USGS) ล้มเหลว จะคงเหตุการณ์เดิมของแหล่งนั้นไว้ อีกแหล่งยังอัปเดตตามปกติ และ `disasters.json` มี `ok: false` กับ `message_th` ให้หน้าเว็บแสดง
  ถ้าล้มเหลวทั้งสองแหล่ง รายการเดิมยังอยู่และงานใน Actions ขึ้นสีแดง แต่ไม่ขวางการอัปเดตราคาและข่าว (และกลับกัน) หน้าเว็บทำเครื่องหมาย “ข้อมูลเก่า” เมื่อไฟล์เก่ากว่า 6 ชั่วโมง
- ถ้าโหลดไฟล์ข้อมูลไม่ได้เลย หน้าเว็บยังแสดงข้อมูลที่ฝังไว้ พร้อมแถบ “โหมดออฟไลน์”

## พัฒนาในเครื่อง

ต้องใช้ Python 3.10 ขึ้นไป (ชุดพัฒนา `anthropic` 2.x ต้องการ 3.10+; GitHub Actions ใช้ 3.12)

```bash
python3 -m venv .venv
.venv/bin/pip install -r updater/requirements-dev.txt

python3 -I tools/build.py                       # สร้าง site/index.html ใหม่ (หลังแก้ gold_module.js ให้รัน tools/splice_gold.py ก่อน)
.venv/bin/python -I updater/update.py --dry-run # ตรวจไฟล์ข้อมูลปัจจุบัน ไม่เรียก API
.venv/bin/python -I updater/prices.py           # ดึงราคา 13 รายการจากแหล่งฟรี (ไม่ใช้คีย์) แล้วเขียน market.json + status.json
.venv/bin/python -I updater/prices.py --data-dir /tmp/data --cost-log /tmp/cost.csv   # ลองกับสำเนาของ site/data
.venv/bin/python -I updater/disasters.py        # ดึงภัยพิบัติจาก GDACS + USGS (ฟรี ไม่ใช้คีย์) แล้วเขียน disasters.json
.venv/bin/python -I updater/disasters.py --check # ตรวจ disasters.json อย่างเดียว ไม่ใช้เน็ต
.venv/bin/python -m pytest updater/tests -q     # ทดสอบหน่วย ไม่ใช้เน็ตและไม่ต้องมีคีย์

cd e2e && PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci && npx playwright test   # ทดสอบหน้าเว็บแบบไม่เปิดหน้าต่าง
```

บน macOS ถ้า Python ฟ้อง `CERTIFICATE_VERIFY_FAILED` ตอนรัน `disasters.py` หรือ `prices.py` ให้ใส่ `SSL_CERT_FILE=/etc/ssl/cert.pem` นำหน้าคำสั่ง (บน GitHub Actions ไม่ต้อง)

ชุดทดสอบหน้าเว็บเปิดเซิร์ฟเวอร์ `e2e/serve.py` ที่ `http://127.0.0.1:18731-18733/global-analysis/` (เปลี่ยนพอร์ตด้วย `E2E_PORT`)
และเก็บภาพหน้าจอไว้ที่ `e2e/shots/`
ชุดทดสอบเดิมตรวจมุมมองลูกโลก จึงตั้งค่าที่เลือกเป็น `map` ไว้ใน `e2e/playwright.config.js` ส่วน `e2e/tests/reading.spec.js` เริ่มจากเบราว์เซอร์ว่างเพื่อทดสอบค่าเริ่มต้นจริง

ดูหน้าเว็บในเครื่อง: `python3 -m http.server 8000 --directory site` แล้วเปิด <http://localhost:8000/>
