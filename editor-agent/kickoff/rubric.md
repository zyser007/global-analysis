# Daily editor run - rubric

Grade each criterion from the session transcript (commands and their output) and from the files in /workspace/global-analysis and the memory store. DATE is the run's Asia/Bangkok date. A criterion that does not apply (for example "if data changed" when nothing changed) passes when the transcript shows why it does not apply.

1. **Health checked.** The transcript shows `editor-agent/check.py --live` output, the newest `site/data/status.json` (ok flag and time), and the bot commits of the last ~26 hours; the final message states whether the live data is healthy. Any unhealthy finding (stale file, `ok: false`, failed bot run, implausible value) has an issue opened or commented (URL shown) or the documented branch fallback.
2. **Change log complete.** `editor-agent/runs/DATE.changes.json` exists and validates; every changed, added or removed item is listed with at least one source that has a URL and a `published` date not after DATE (new conflicts: at least two sources from different publishers). Shown by `check.py --all --base <BASE> --run-date DATE` reporting 0 errors.
3. **No invented or undated content.** Every source URL in the change log was opened with web_fetch or appeared in a web_search result in this session. Changed texts are Thai (proper nouns may be English), neutral, and put an explicit date next to events; no title (`meta.title`, `name_th`, gold `title_th`) contains a month, a year or an undated "now" word.
4. **Dates consistent.** If world data changed: `meta.updated` = DATE and `meta.basis_th` ends with DATE in Thai. If gold changed: `as_of` is the time of the spot price used and `updated_th` contains its Bangkok date. (Covered by check.py with 0 errors.)
5. **Page rebuilt and verified.** The transcript shows `tools/build.py` run after the last data edit, then: `check.py --all ...` with 0 errors, `pytest updater/tests editor-agent/tests` all passed, `visual_check.py` with 0 errors, and `e2e.sh` run with its result explained (only failures that compare against old hard-coded data values or counts, or exit code 3, may be left unresolved, and they are listed in the run log).
6. **Published within limits.** Either (a) a commit on origin/main containing only the allowed files, verified by `check.py --scope` and by HEAD = origin/main after push, with no force push; or (b) when a check could not pass, nothing pushed to main and the work pushed to `agent/DATE-...` with an issue; or (c) nothing changed and only the run log was committed. Code or layout proposals are only on `agent/*` branches with an issue.
7. **Run summary written.** `editor-agent/runs/DATE.md` exists in the pushed commit (or branch), in Thai, listing what changed with links, what was reviewed without change, live-data health, e2e notes, and issues/branches.
8. **Memory updated.** The memory store has `runs/DATE.md` (outcome, commit SHA or branch, items changed, searches and fetches used, problems), and `known-issues.md` / `open-decisions.md` / `watchlist.md` were updated when this run learned something new. No secret appears in memory.
9. **Search budget respected.** At most 40 web_search and 25 web_fetch calls, stated in the final message.
10. **Final message.** In Thai, under 25 lines, with: DATE, result and commit SHA (or branch), number and keys of changed items, the summary lines of check.py / pytest / visual_check.py / e2e.sh, live-data health, issue and branch URLs, and decisions waiting for the owner.
